# 抽奖前置规则配置

前置规则按活动参与规则版本保存。一个责任链节点对应
`lottery_pre_draw_rules` 中的一行，节点自己的内容保存在 `rule_config JSON`。

## 表结构

`lottery_pre_draw_rules` 保存活动、规则版本、规则类型、执行顺序、启停状态和
`rule_config`。不同节点使用紧凑的 JSON 结构：

```json
// USER_LIST：用户ID数组
[1001, 1002]

// PRIZE_UNLOCK：奖品ID -> 最低抽奖次数
{"101": 3, "102": 5}

// POINTS_WEIGHT：最低积分 -> (奖品ID -> 权重倍数)
{"10": {"101": 1.5}, "50": {"101": 2, "102": 1.2}}

// LUCKY_FALLBACK：幸运奖奖品ID
999
```

## 后端读取模型

持久化模块将 `rule_config` 组装成强类型参数：

- 名单：`Set<Long>`。
- 解锁条件：`Map<Long, Long>`，键为奖品 ID，值为最低抽奖次数。
- 积分权重：积分档位列表，每个档位包含 `Map<Long, BigDecimal>` 权重倍数。
- 幸运奖：`Long prizeId`。

JSON 的序列化和解析集中在持久化模块。责任链只接收强类型定义，规则节点本身
不依赖 `ObjectMapper`、`JsonNode` 或字符串解析。

管理接口仍通过 HTTP JSON 传输请求，但字段固定为 `userIds`、
`prizeMinimumDrawCounts` 和 `pointsTiers`，不存在任意结构的 `config` 字段。

`activity_participation_rules` 只保存积分成本、每日次数和规则版本；
`lottery_prizes` 只保存基础奖池。规则变更时新增参与规则版本并复制基础奖池，
历史抽奖单继续关联原规则版本。
